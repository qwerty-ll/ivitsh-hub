# ИВИТШ Хаб — план превращения портала в единую площадку института

Этот файл — полный контекст для работы над проектом в новом чате с Claude.
Он заменяет всю переписку, в которой проект обсуждался: здесь цель, принятые решения,
устройство текущего кода, полный список идей и порядок работ.

> **Как начать работу в новом чате:** «Прочитай docs/ROADMAP.md, начинаем этап N».
> После каждого этапа обновляй раздел «Статус этапов» в конце этого файла.

## 1. Откуда проект и куда идём

**Было:** CombinedPortal (`qwerty-ll/CombinedPortal`) — портал ИВИТШ КГУ, изначально
«гид первокурсника»: путь адаптации из 9 этапов, квиз, чек-лист, награды, мини-игры,
плюс форум, расписание ЭИОС, карта корпуса Б, преподаватели, FAQ, ИИ-помощник ВИТШик.

**Станет:** `qwerty-ll/ivitsh-hub` (приватный репозиторий, копия CombinedPortal со всей
историей коммитов) — **единая площадка студентов института ИВИТШ**: общий календарь,
студенческие объединения, задачи с канбаном, мероприятия, документы для ПГАС,
бронь коворкинга 108, уведомления через бота ВК, аналитика для руководителей и администрации.

Гид первокурсника **убираем полностью** (см. раздел 4). Всё остальное полезное — оставляем.

## 2. Принятые решения (не пересматривать без запроса пользователя)

| Вопрос | Решение |
|---|---|
| Репозиторий | Отдельный приватный `qwerty-ll/ivitsh-hub`, перенесён из CombinedPortal с историей |
| Гид первокурсника | Удалить целиком (страница, адаптация на сервере, вкладка админки, мини-игры, блок на главной) |
| Форум | **Оставляем** |
| ВИТШик (ИИ-агент на GigaChat) | Оставляем; позже научить его отвечать про задачи, собрания, мероприятия |
| Карта, преподаватели, FAQ, документы от ВИТШика | Оставляем |
| Пароль СДО и ЭИОС | **Один и тот же.** При входе через ЭИОС тем же логином/паролем получаем токен Moodle СДО и подтягиваем курсы студента (ссылки на курсы в календаре). Пароль **не храним**. |
| Уведомления | **Бот ВКонтакте** (сообщество ВК). Не Telegram, не Web Push. |
| Контакты для связи | Студент может указать ВК и Max в профиле — руководитель видит их. **Telegram не добавляем** (решение пользователя) |
| Список администраторов | Будет позже (известно: «Егор» и «ТВ»). Права `admin` выдаёт и снимает только главный администратор (учётная запись из `.env`) в админ-панели |
| БД в git | Никогда. `*.db`, `.env` в `.gitignore`; в репозитории только код и `.env.example` |

## 3. Устройство текущего кода (на момент переноса)

**Стек:** React 18 + Vite (SPA, `client/`), Python 3.11 + FastAPI (`server/`), SQLAlchemy +
Alembic (миграции `server/migrations/versions/0001…0005`), SQLite локально / PostgreSQL в Docker,
Nginx, Docker Compose. PWA (ставится на главный экран, `client/public/sw.js`, `manifest.webmanifest`).

**Команды** (`package.json` в корне):
- `npm run dev` — клиент, `npm run server` — API на :8000
- `npm test` — `pytest` в `server/tests`
- `npm run migrate` — применить миграции
- CI (`.github/workflows/ci.yml`): pytest, **`alembic check` (модели должны совпадать с миграциями —
  на каждую правку моделей нужна новая миграция)**, `npm run build`, `npm audit`, проверка nginx,
  сборка и smoke-тест docker compose.

**Сервер (`server/app/`):**
- `models/models.py` — `User` (role: `student | curator | moderator | admin`, `group_number`,
  `eios_group_id`, `sdo_id`, `auth_source`, `is_blocked`, `avatar_url`, согласие ПД),
  `ForumQuestion/Answer`, `Vote`, `Teacher`, `Announcement`, `FaqItem`, `Subject`,
  `RevokedToken`, `UserAdaptation` (удаляется).
- `routers/`: `auth` (вход через ЭИОС `/eios-login`, локальный админ `/admin-login`, `/me`),
  `forum`, `chat`, `schedule`, `documents`, `admin`, `rooms`, `adaptation` (удаляется).
- `services/`: `eios.py` (вход и карточка студента ЭИОС), `timetable.py` (расписание ЭИОС с кэшем),
  `assistant.py` + `agent.py` + `rag_service.py` (ВИТШик), `documents.py` + `document_drafts.py`
  (Word/PDF объяснительные — **переиспользовать для выгрузок ПГАС**), `rooms.py`.
- `core/security.py` — JWT в httpOnly-куке, CSRF, `require_current_user`, `require_admin`,
  `require_moderator`. `core/rate_limit.py`. `core/config.py` — переменные окружения.
- `assets/rooms.json` — база аудиторий. **Аудитория 108 = коворкинг «8 бит», 1 этаж, 50 мест.**
- Документация API: `docs/SDO_AND_EIOS_AUTH_API.md` (Moodle REST: `core_enrol_get_users_courses`,
  `mod_assign_get_assignments` и др., получение `wstoken` через `login/token.php`),

**Клиент (`client/src/`):**
- `App.jsx` — маршруты: `/`, `/guide` (удаляется), `/forum`, `/forum/question/:id`, `/map`,
  `/teachers`, `/faq`, `/profile`, `/admin`, `/privacy`.
- `data/sections.js` — единый список разделов (название, путь, иконка, цвет), `NAV_ORDER`,

- `services/api.js` — все запросы к API.
- `context/AuthContext.jsx`, `context/ToastContext.jsx`.
- `components/ScheduleWidget.jsx` — расписание (основа для календаря), `ChatWidget.jsx` — ВИТШик,

- Стили: `styles/tokens.css` (дизайн-токены), `shared.css`, по файлу на раздел. Дизайн — `docs/DESIGN.md`.

**Стиль кода:** комментарии в коде по-английски, короткие; весь интерфейс — по-русски.
Тесты на каждую новую серверную функцию (`server/tests`, фикстуры в `conftest.py`, есть `fake_eios`).

## 5. Полный список идей (от пользователя)

### 5.1. Для участников объединений (студентов)

**Расписание и учёба**
- **Общий календарь:** единый календарь, где видны пары, аудитории, прямые кликабельные ссылки на
  курсы в СДО (если есть), время встреч своего объединения и открытые мероприятия института
  (или те, на которые студент записался).
  Вид: на компьютере — неделя сеткой с цветными блоками (как Google Календарь),
  на телефоне — список по дням с карточками пар (как в ЭИОС: время, предмет, преподаватель,
  аудитория).
- **ДЗ внутри группы:** внутри своей академической группы записывать ДЗ, дедлайны и заметки,
  чтобы одногруппники могли зайти и сразу всё увидеть.

**Объединения и задачи**
- **Каталог объединений:** список всех объединений института, контакты руководителей
  (ТГ, ВК, Max) и кнопка «Подать заявку» (вступление после подтверждения руководителем).
- **Страница задач:** отдельный раздел с задачами, фильтрами по объединениям и статусами
  «К выполнению», «В работе», «На проверке», «Готово» (канбан).
- **Файлы и обсуждение:** прикреплять к задачам макеты, сценарии, регламенты или ссылки;
  комментарии под задачей для связи с руководителем.
- **Личные задачи:** блок для своих заметок и задач (как в Google Календаре), задачи самому себе,
  выделение разными цветами.
- **Контакты:** возможность прикрепить ТГ, ВК или Max, чтобы руководитель мог связаться со студентом.

**Мероприятия, уведомления и ПГАС**
- **Запись на мероприятия** (участником или волонтёром) в один клик. После окончания мероприятия
  участнику приходит короткий опрос (оценка по 5-балльной шкале и отзыв).
- **Гибкие напоминания:** настраиваемые (за сколько напомнить о мероприятии; о дедлайне задачи
  за день до сдачи). Канал — бот ВК.
- **Достижения в профиле:** автоматически «Участник объединения [Название]».
- **Сводка за семестр для ПГАС:** выгрузка списка всех мероприятий, где студент участвовал.
  1. Руководитель прикрепляет к событию PDF распоряжений, освобождений и благодарностей —
     они сразу доступны студенту для скачивания.
  2. Если мероприятия не было на портале, студент вносит его вручную и позже прикрепляет скан
     распоряжения (запись можно редактировать).

### 5.2. Для руководителей объединений

**Управление объединением и участниками**
- **Модерация заявок:** одобрение или отклонение заявок на вступление.
- **Достижение:** автоматически «Руководитель объединения [Название]» в профиле и в достижениях.
- **Инфо-блок / объявления объединения:** важная информация, объявления и материалы — точечно
  конкретным людям или на всё объединение (как «Объявления» в СДО): ссылка на чат, распоряжение и т. п.

**Работа с задачами**
- **Постановка задач:** на конкретных людей или на всё объединение разом.
- **Контроль выполнения:** статусы задач у участников, проверка прикреплённых файлов,
  обратная связь через комментарии или ЛС (если студент указал ВК, ТГ или Max).

**Организация мероприятий и встреч**
- **Собрания объединения:** встреча в календаре (время и место сразу видны участникам)
  + краткое описание, о чём была встреча.
- **Создание мероприятий** любого формата (внутри объединения или института). **Руководитель
  не может записать на мероприятие целую академическую группу** — только пофамильно;
  группой — по запросу к администрации.
- **Списки участников:** руководитель сам записывает людей, удаляет, выгружает в конце семестра.
- **Загрузка документов:** PDF с распоряжениями и благодарностями к карточке прошедшего события.

**Бронь аудитории 108 (коворкинг «8 бит») и оборудования**
- Сетка бронирования: занять «верх», «низ» или всё помещение целиком.
- Защита от накладок: занятый слот для остальных руководителей блокируется автоматически
  («всё помещение» конфликтует и с «верхом», и с «низом»).
- Бронь ноутбуков: отдельно, всего 5 штук (нельзя выдать больше 5 одновременно).

**Статистика по участникам (дашборд руководителя)**
1. Сколько раз участник был на собраниях.
2. В скольких мероприятиях участвовал.
3. Сколько дедлайнов просрочил и сколько закрыл вовремя (считается по времени перехода задачи
   в «Готово»/«На проверке» относительно дедлайна).

### 5.3. Для администрации

**Аналитика посещаемости и активности**
- Статистика по курсам: сколько зарегистрировано и сколько реально заходит
  (например, 1 курс — 100, 2 курс — 60, 3 курс — 30).
- Критерий активности: заходил хотя бы раз за семестр — активный, ни разу — неактивный.
- Единый список студентов: выгрузка с сортировкой по академическим группам и по ФИО.

**Контроль объединений и событий**
- Выгрузка участников любых объединений (только админ).
- **Назначение групп на мероприятие:** только администрация (Егор, ТВ) может прикрепить к
  мероприятию целую академическую группу или несколько. Защита от спама.
- Популярность мероприятий: какие события собирают больше людей.

### 5.4. На будущее
- **Роль старосты группы:** закреплять объявления для своей академической группы.
- **«Гайды по документам»:** база знаний (матпомощь, социальная стипендия, справка об обучении).
  Делать не «на будущее», а развитием текущего раздела FAQ.
- **ИВИТШ Медиа / Новости:** новостная лента (посты, фотоотчёты о мероприятиях), по образцу
  новостей на главной сайта КГУ. Можно вырастить из существующих `Announcement`.

## 6. Модель данных (набросок, уточнять при реализации)

Роли на всём портале остаются в `User.role` (`student | moderator | admin`; `curator` —
проверить, используется ли, иначе не трогать). **Роль внутри объединения — отдельная таблица.**

- `User` + поля: `vk_url`, `max_contact` (контакты, видимы руководителям своих
  объединений), `vk_user_id` (привязка к боту ВК), `last_seen_at` (для «активен за семестр» —
  обновлять не чаще раза в N минут, например в `get_current_user`), `course` (курс из ЭИОС,
  если есть в карточке студента).
- `Association` (объединение): название, описание, логотип, контакты, `is_active`.
- `Membership`: `user_id`, `association_id`, `role` (`member | leader`), `status`
  (`pending | approved | rejected | left`), даты. Уникальность (user, association).
- `Task`: `association_id` (null = личная), `created_by`, `title`, `description`, `due_at`,
  `color` (для личных), `status` (`todo | in_progress | review | done`).
- `TaskAssignee`: `task_id`, `user_id`, свой статус у каждого исполнителя, `status_changed_at`,
  `completed_at` (для статистики «вовремя / просрочено»). «На всё объединение» = создать
  исполнителя для каждого участника в момент постановки.
- `TaskComment`, `Attachment` (универсальная: владелец-объект + файл или ссылка).
- `GroupHomework`: `group_number`, `subject`, `text`, `due_at`, `created_by` (видят все из группы).
- `Meeting` (собрание объединения): время, место (можно связать с бронью), итоги встречи;
  `MeetingAttendance` — кто был.
- `Event` (мероприятие): организатор (объединение или администрация), видимость
  (объединение / институт), время, место, лимиты участников/волонтёров.
- `EventRegistration`: `user_id`, `role` (`participant | volunteer`), `source`
  (`self | leader | admin_group`), `attended`.
- `EventFeedback`: оценка 1–5 + отзыв (одна на студента и событие).
- `EventDocument`: PDF распоряжений/освобождений/благодарностей к событию.
- `ManualAchievement`: мероприятие, внесённое студентом вручную, + скан; редактируемое.
- `Achievement` — можно не хранить, а вычислять (членство, руководство, участие).
- `AssociationPost` (объявление объединения): адресаты — всё объединение или список людей.
- `RoomBooking`: помещение 108, `zone` (`top | bottom | whole`), `start_at`, `end_at`, `booked_by`,
  `association_id`. `LaptopBooking`: количество (1–5), интервал.
- `Reminder` / `NotificationSetting`: настройки напоминаний пользователя; очередь отправки.
- `SdoCourse`: курсы студента из СДО (id, название, ссылка), обновляются при входе;
  сопоставление с предметом расписания — по названию (с ручной правкой админом при несовпадении).

## 7. Технические заметки и подводные камни

- **СДО (Moodle):** при `/eios-login` тем же логином/паролем запросить `wstoken`
  (`https://sdo.kosgos.ru/login/token.php`, см. `docs/SDO_AND_EIOS_AUTH_API.md`), затем
  `core_webservice_get_site_info` → `core_enrol_get_users_courses`. Сохранить только список курсов.
  Пароль не сохранять. Токен — либо не хранить вовсе (обновлять курсы при каждом входе), либо
  хранить зашифрованным, если понадобятся дедлайны `mod_assign_get_assignments`. Ошибка СДО
  **не должна** ломать вход в портал. Проверить, что сервис `moodle_mobile_app` (или другой)
  доступен на sdo.kosgos.ru.
- **Бот ВК:** нужно сообщество ВК ИВИТШ с включёнными сообщениями и ключом доступа сообщества
  (`VK_GROUP_TOKEN`, `VK_GROUP_ID` в `.env`). **Бот может писать только тем, кто разрешил
  сообщения сообществу / написал ему первым.** Привязка: в профиле кнопка «Подключить уведомления
  ВК» → ссылка на диалог с сообществом с одноразовым кодом (`vk.me/<группа>?ref=<код>` или

## 8. Этапы работ

Каждый этап выкатывается отдельно. Порядок выбран так, чтобы после этапов 1–2 портал уже был
полезен объединениям.

0. **Удалить гид первокурсника** (раздел 4). Переименовать проект в «ИВИТШ Хаб».
1. **Фундамент:** `Association`, `Membership`, каталог объединений, заявки и их модерация,
   контакты (ТГ/ВК/Max) в профиле, `last_seen_at`, достижения «Участник/Руководитель».
   Админ создаёт объединения и назначает руководителей.
2. **Задачи:** канбан (4 статуса), постановка на людей/на всё объединение, комментарии,
   файлы и ссылки, личные задачи с цветами, объявления объединения.
3. **Общий календарь:** пары ЭИОС + курсы СДО (ссылки) + собрания + мероприятия + личные задачи
   + ДЗ группы. Неделя сеткой (ПК) и список по дням (телефон). На главной — «Сегодня» и «Мои задачи».
4. **Мероприятия и ПГАС:** создание, запись участником/волонтёром, запись группы (админ),
   опрос после события, документы PDF, ручные мероприятия со сканом, выгрузка за семестр.
5. **Бронь 108 и ноутбуков.**
6. **Бот ВК и напоминания:** привязка, настройки, напоминания о мероприятиях и дедлайнах,
   уведомления о новых задачах, решениях по заявкам, объявлениях.
7. **Дашборды:** руководителя (собрания, мероприятия, дедлайны по участникам) и администрации
   (активность по курсам, список студентов, выгрузки, популярность мероприятий).
8. **На будущее:** старосты, «Гайды по документам» (из FAQ), ИВИТШ Медиа / новости.
