# Что нового в ИВИТШ Хабе

## Этап 5: бронь коворкинга 108 и ноутбуков

- **Раздел «Бронь 108»** (`/booking`): день сеткой в три дорожки — «Верх», «Низ» и «Ноутбуки»; бронь всего
  помещения растягивается на обе части. Нажатие на свободное время открывает форму с этим временем.
- **Бронируют** руководители объединений (для своего объединения) и администрация (для себя или любого
  объединения). Остальные вошедшие видят, когда помещение и ноутбуки заняты.
- **Бронь подтверждается сразу.** Время — любое с шагом 5 минут, не меньше 15 минут, в часы работы
  коворкинга (08:00–21:00, настраивается), в пределах одного дня и не дальше чем на 90 дней вперёд.
- **Без накладок:** «всё помещение» пересекается и с «верхом», и с «низом»; сервер говорит, кем и до скольки
  занято. Ноутбуков в любой момент не больше 5: считается пиковая занятость на интервале, так что две брони,
  идущие друг за другом, не складываются. Проверка и запись идут под блокировкой (в PostgreSQL —
  `pg_advisory_xact_lock`), чтобы две одновременные брони не прошли обе.
- **Отмена:** автор отменяет свою бронь, администрация — любую, с причиной. В «Моих бронях» отменённая
  видна с причиной и тем, кто отменил. (Сообщение в ВК — этап 6.)
- Свои брони видны в календаре.
- Миграция `0011`: `bookings`. Новые переменные `.env` (необязательные): `BOOKING_OPEN`, `BOOKING_CLOSE`,
  `LAPTOPS_TOTAL`.

| Метод | Что делает |
|---|---|
| `GET /api/v1/bookings?day=YYYY-MM-DD&days=1` | брони дня (часы работы, число ноутбуков, можно ли бронировать) |
| `GET /api/v1/bookings/mine` | мои брони, в том числе отменённые |
| `POST /api/v1/bookings` | забронировать (`resource`: `room` + `zone` или `laptops` + `laptops`) |
| `POST /api/v1/bookings/{id}/cancel` | отменить (`reason` — для администрации) |

## Этап 4: мероприятия и ПГАС

- **Раздел «Мероприятия»** (`/events`): вкладки «Предстоящие», «Мои», «Прошедшие», «Организую» (для
  организаторов) и «ПГАС». Карточка показывает время, место, организатора и занятые места.
- **Два уровня.** Мероприятие объединения создаёт его руководитель — его видят участники объединения.
  Мероприятие института создаёт **только администрация** — его видят все (и гости, без записи); организатором
  можно указать объединение, тогда его руководитель тоже управляет списком и документами.
- **Запись в один клик** участником или волонтёром, с лимитами мест; можно сменить роль или отменить запись
  до окончания. Мероприятия появляются в календаре (красные) — и те, куда записан, и открытые.
- **Организаторы** записывают людей пофамильно (руководитель — только участников своего объединения,
  администрация — кого угодно), убирают из списка, после начала отмечают присутствие и выгружают список в Excel.
  **Академическую группу целиком записывает только администрация** — несколько групп через запятую.
- **Документы**: к мероприятию прикрепляются PDF распоряжений, освобождений и благодарностей — их сразу
  скачивают все записавшиеся (и только они).
- **Опрос после мероприятия**: оценка 1–5 и отзыв. Напоминание — на главной и в разделе; организаторы видят
  среднюю оценку и отзывы без имён. (Сообщения в ВК — на этапе 6.)
- **Сводка для ПГАС** за семестр (осень — сентябрь–январь, весна — февраль–август): мероприятия с портала
  (кроме тех, где отмечено отсутствие) и внесённые вручную, со ссылками на документы. Мероприятие не с
  портала студент вносит сам и прикрепляет скан; запись можно править. Выгрузка — **Excel и Word**.
- **Права администратора** выдаёт и снимает только Главный Администратор (учётная запись из `.env`); он же
  блокирует и удаляет других администраторов. Остальные администраторы назначают модераторов.
- Мероприятия — ярлык на главной (вместо FAQ, он остался в меню) и блок на странице объединения.
- Миграция `0010`: `events`, `event_registrations`, `event_feedback`, `manual_achievements`,
  `attachments.event_id`, `attachments.achievement_id`. Новая зависимость — `openpyxl`. nginx пропускает
  файлы до 11 МБ и на адреса загрузки к мероприятиям и достижениям. /privacy и согласие дополнены.

| Метод | Что делает |
|---|---|
| `GET /api/v1/events?view=upcoming\|past\|mine\|managed&association_id=` | список |
| `POST /api/v1/events`, `GET/PUT/DELETE /api/v1/events/{id}` | мероприятие |
| `POST/DELETE /api/v1/events/{id}/register` | записаться (`role`) / отменить |
| `POST /api/v1/events/{id}/registrations`, `DELETE …/registrations/{user_id}` | организатор записывает / убирает |
| `POST /api/v1/events/{id}/groups` | записать группы (только администрация) |
| `PUT /api/v1/events/{id}/attendance` | кто был |
| `POST /api/v1/events/{id}/feedback`, `GET /api/v1/events/feedback/pending` | опрос |
| `GET /api/v1/events/{id}/export` | список в Excel |
| `POST /api/v1/events/{id}/files?name=`, `…/links` | документы |
| `GET/POST /api/v1/achievements`, `PUT/DELETE …/{id}`, `POST …/{id}/files?name=` | внесённые вручную |
| `GET /api/v1/portfolio?start=&end=`, `GET /api/v1/portfolio/export?format=xlsx\|docx` | сводка ПГАС |

## Этап 3: общий календарь

- **Раздел «Календарь»** (`/calendar`) — в одном месте пары группы из ЭИОС, собрания объединений, дедлайны
  задач и ДЗ группы. На компьютере — неделя сеткой с цветными блоками (пары синие, собрания оливковые,
  задачи бирюзовые или своего цвета, ДЗ фиолетовые), сроки — отдельной строкой над сеткой, красная линия —
  текущее время. На телефоне — полоска дней недели и карточки выбранного дня (время, предмет, вид занятия,
  аудитория, преподаватель). Фильтры по видам записей и выбор своей подгруппы запоминаются в браузере.
- **Карточка пары**: время, аудитория (ссылка на карту), преподаватель, «Замена»; кнопка **«Курс в СДО»**, если
  курс нашёлся, и «Записать ДЗ» с уже подставленным предметом.
- **Курсы СДО**: при входе через ЭИОС тем же логином и паролем портал запрашивает у СДО КГУ (Moodle) список
  курсов студента — уже после ответа на вход, так что вход не замедляется и не ломается, если СДО недоступна.
  Сохраняются только номера и названия курсов, пароль и токен — нет. Курс сопоставляется с предметом по
  названию («Базы данных (2026-2027)» ↔ «Базы данных»). Полный список курсов — под календарём.
- **ДЗ группы**: любой студент группы записывает задание, срок и предмет (или заметку без срока) — запись
  видят все одногруппники. Изменить и удалить может автор (и модераторы).
- **Собрания объединения**: руководитель назначает собрание (дата, время, место, о чём) на странице
  объединения или из календаря — оно появляется в календаре у всех участников. После начала руководитель
  отмечает, кто пришёл, и записывает итоги встречи; участники видят итоги в прошедших собраниях.
- **Главная для вошедших**: вместо карточки расписания — «Сегодня» (пары, собрания и сроки на сегодня,
  а когда день закончился — следующий день с записями) и «Мои задачи» (открытые задачи, ближайший срок
  первым). Блок «Знакомство с порталом» остался только у гостей.
- **Нижняя панель на телефоне**: «Главная, Календарь, Задачи, Объединения, Профиль»; у гостей вместо
  календаря — «Расписание». Раздел «Расписание» (любая группа, преподаватель, аудитория) остался в меню и по
  ссылке из календаря.
- Миграция `0009`: `meetings`, `meeting_attendance`, `group_homework`, `sdo_courses`, `users.sdo_synced_at`.
  Новые переменные `.env`: `SDO_BASE_URL`, `SDO_SERVICE`. Страница /privacy и текст согласия дополнены
  (курсы СДО, собрания, ДЗ группы).

| Метод | Что делает |
|---|---|
| `GET /api/v1/calendar?start=YYYY-MM-DD&days=7` | записи календаря (до 42 дней), статус пар: `ok / stale / unavailable / no_group` |
| `GET /api/v1/calendar/courses` | мои курсы СДО со ссылками |
| `GET/POST /api/v1/associations/{id}/meetings?past=` | собрания объединения |
| `GET/PUT/DELETE /api/v1/meetings/{id}` | собрание |
| `PUT /api/v1/meetings/{id}/attendance` | кто был (руководитель, после начала) |
| `GET /api/v1/homework?past=`, `POST /api/v1/homework`, `PUT/DELETE /api/v1/homework/{id}` | ДЗ группы |

## Этап 2: задачи и объявления объединений

- **Раздел «Задачи»** (`/tasks`) — канбан из четырёх колонок: «К выполнению», «В работе», «На проверке»,
  «Готово». Карточку можно перетащить мышью или сменить статус в самой карточке; на телефоне колонки
  переключаются кнопками 2×2. Фильтр: все, личные или задачи одного объединения. У карточки — дедлайн
  («Сегодня, 18:00», красным — просрочено), счётчики комментариев, файлов и исполнителей.
- **Личные задачи** — себе, с цветом (6 цветов) и дедлайном; статус любой, в том числе «Готово».
- **Руководитель** ставит задачу своему объединению: всем участникам сразу или выбранным (кнопка
  «Новая задача» или «Поставить задачу» на странице объединения). У каждого исполнителя своя карточка.
  Вкладка «Поставленные» показывает, сколько сдали и сколько ждут проверки. На странице задачи — список
  исполнителей со статусами, «сдано вовремя / с опозданием», кнопки «Принять» и «На доработку», добавить
  или снять исполнителя, изменить и удалить задачу.
- **Исполнитель** двигает свою карточку до «На проверке»; «Готово» ставит руководитель после проверки.
- **Файлы и ссылки** у задачи: PDF, изображения, Word, Excel, PowerPoint, ZIP до 10 МБ. Тип проверяется по
  содержимому, файлы хранятся на сервере (не в базе и не в git) и скачиваются только теми, кому видна задача.
- **Обсуждение** под задачей объединения — для исполнителей и руководителя.
- **Объявления объединения** на его странице: руководитель пишет всем участникам или выбранным и прикрепляет
  файлы (распоряжения, благодарности) и ссылки (чат). Участник видит только адресованное ему.
- На телефоне в нижней панели теперь «Главная, Расписание, Задачи, Объединения, Профиль»; форум, карта,
  преподаватели и FAQ — ярлыками на главной и в меню.
- Контакты для связи — только ВКонтакте и Max (Telegram убран).
- Миграция `0008`: `tasks`, `task_assignees`, `task_comments`, `association_posts`,
  `association_post_recipients`, `attachments`. Новые переменные `.env`: `UPLOAD_DIR`, `MAX_UPLOAD_MB`.
  В Docker файлы лежат в томе данных; nginx принимает до 11 МБ только на адреса загрузки.

| Метод | Что делает |
|---|---|
| `GET /api/v1/tasks/my?personal=&association_id=` | мои карточки |
| `GET /api/v1/tasks/managed` | задачи, которые я поставил как руководитель |
| `POST /api/v1/tasks`, `GET/PUT/DELETE /api/v1/tasks/{id}` | задача |
| `PATCH /api/v1/tasks/{id}/status` | статус своей карточки или (руководитель) чужой |
| `DELETE /api/v1/tasks/{id}/assignees/{user_id}` | снять исполнителя |
| `POST /api/v1/tasks/{id}/comments`, `DELETE /api/v1/tasks/comments/{id}` | обсуждение |
| `POST /api/v1/tasks/{id}/files?name=`, `POST /api/v1/tasks/{id}/links` | файл (тело запроса — сам файл) и ссылка |
| `GET/POST /api/v1/associations/{id}/posts`, `DELETE /api/v1/associations/posts/{id}` | объявления |
| `POST /api/v1/associations/posts/{id}/files?name=`, `…/links` | файлы и ссылки объявления |
| `GET /api/v1/attachments/{id}`, `DELETE /api/v1/attachments/{id}` | скачать / удалить |

## Этап 1: студенческие объединения

- **Раздел «Объединения»** (`/associations`) — каталог 21 объединения ИВИТШ из списка института: поиск,
  руководитель, число участников, ваш статус. Фильтр «Мои» для вошедших.
- **Страница объединения**: описание, «где нас найти», руководитель с контактами (видны только вошедшим),
  заявка на вступление с парой слов о себе, отзыв заявки, выход из объединения.
- **Руководитель** на странице своего объединения видит «Управление»: заявки (принять / отклонить),
  участников с группой и контактами (исключить), редактирует описание и контакты объединения.
- **Панель управления → «Объединения»**: создать, изменить, скрыть из каталога или удалить объединение;
  назначить и снять руководителя (поиск по ФИО, логину, группе). У объединений из списка института
  записано ФИО руководителя: когда этот человек впервые войдёт через ЭИОС, появится кнопка
  «Назначить: …». До этого в каталоге показано ФИО из списка (без контактов).
- **Профиль**: «Контакты для связи» (ВКонтакте и Max — ссылкой или ником, всё необязательно)
  и «Объединения и достижения» — «Участник / Руководитель объединения «…»» и заявки на рассмотрении.
- **ВИТШик** отвечает про объединения из каталога: «кто руководит спортивным программированием»,
  «какие есть клубы» — с кнопкой на страницу объединения.
- Портал запоминает время последнего визита (не чаще раза в 10 минут) — для статистики активности на этапе 7.
- `/privacy` и текст согласия дополнены: контакты, участие в объединениях, время визита.
- Миграция `0007`: таблицы `associations`, `memberships`, поля пользователя `vk_url`,
  `max_contact`, `last_seen_at`. Каталог заполняется из `server/app/db/seeds/associations.json` при первом
  запуске (если таблица пуста).

| Метод | Что делает |
|---|---|
| `GET /api/v1/associations`, `GET /api/v1/associations/{id}` | каталог и страница объединения |
| `GET /api/v1/associations/mine` | мои заявки и участие |
| `POST /api/v1/associations/{id}/apply`, `DELETE /api/v1/associations/{id}/membership` | заявка, отзыв / выход |
| `PUT /api/v1/associations/{id}` | описание и контакты (руководитель) |
| `POST …/members/{user_id}/decision`, `DELETE …/members/{user_id}` | решение по заявке, исключение |
| `GET/POST/PUT/DELETE /api/v1/admin/associations…`, `PUT/DELETE …/leaders/{user_id}` | администрирование |
| `PATCH /api/v1/auth/me` | новые поля `vk_url`, `max_contact` |
| `GET /api/v1/admin/users?q=` | поиск пользователей |

## ИВИТШ Хаб, этап 0: гид первокурсника удалён

Портал переименован в **ИВИТШ Хаб** и становится единой площадкой студентов института
(план — `docs/ROADMAP.md`). Гид первокурсника убран целиком:

- страница `/guide`, её пункт в меню и на нижней панели, кнопка «Путь первокурсника» на главной;
- карточка «Путь адаптации» и мини-игры в личном кабинете, вкладка «Адаптация студентов» в панели управления;
- ежедневное браузерное напоминание об адаптации (уведомления позже придут через бота ВК);
- API `POST /api/v1/adaptation`, `GET /api/v1/adaptation/me`, `GET /api/v1/admin/adaptations`
  и таблица `user_adaptations` (миграция `0006`, применяется сама при старте);
- ВИТШик больше не предлагает кнопку «Путь первокурсника»;
- из текста согласия убран «прогресс адаптации», редакция — 30 сентября 2026 г.

Старые ключи гида в браузере (`freshman_roadmap_completed`, `vitshik_…`, `ivitsh_last_daily_notif`)
удаляются при следующем открытии портала. Справочник дисциплин в панели управления остался.

## Главная без перегруза: отдельный раздел «Расписание»

- **Новый раздел `/schedule`** — полное расписание (группы, преподаватели, аудитории, день и неделя). Он есть
  в меню и на нижней панели телефона; туда же ведут кнопки ВИТШика и ярлык приложения.
- **На главной — карточка «Сегодня»** вместо полного расписания с фильтрами: только ближайшие пары своей
  группы, прошедшие свёрнуты в одну строку. Когда пары на сегодня закончились — показывает «Завтра»
  (или ближайший учебный день). Ссылка «Всё расписание» ведёт в раздел.
- **Для преподавателей и гостей**: на главной вместо чужой группы — выбор «Выбрать группу / Я преподаватель».
  Преподаватель один раз находит себя в расписании, и дальше главная показывает его пары (без входа).
- На телефоне карточка «Сегодня» стоит сразу под приветствием; ярлыки разделов — сеткой 2×2, ничего
  не обрезается у края экрана. Пустой блок «Объявления» скрыт, пока объявлений нет.
- Вкладка входа «Сотрудник ИВИТШ» переименована в «Администратор» с пояснением, что преподавателям
  вход не нужен.
- Исправлено: с полуночи до 3:00 расписание открывалось на вчерашнем дне (дата считалась по UTC).

## Главное

- **ВИТШик — ИИ-агент**: GigaChat понимает вопрос своими словами и сам вызывает функции портала
  (расписание ЭИОС, аудитории, преподаватели, поиск по базе); факты — только из них, без выдумок.
- **ВИТШик пишет документы**: объяснительная и заявление на пересдачу в Word или PDF, уже заполненные.
- **Где сейчас преподаватель**: «На паре в Б-305 до 11:40», «Свободна до 13:40».
- **Новая карта корпуса Б**: векторные схемы 4 этажей, аудитория подсвечивается и отмечается булавкой;
  у каждой — места, ПК, ноутбуки, ОС, техника и свободна ли она сейчас.
- **Приложение на телефон**: портал ставится на главный экран и открывается как отдельное приложение.
- **Cookie и согласие по 152-ФЗ**: уведомление на всех страницах, политика и отдельное согласие при входе.
- **GigaChat работает из коробки**: сертификаты Минцифры встроены в портал.
- **Новый дизайн**, настоящие ФИО и группа из ЭИОС, запуск одной командой `docker compose up`.

## Для студента

**Вход и профиль**
- Вход через ЭИОС; ФИО и группа берутся из карточки студента ЭИОС, расписание сразу открывается на своей группе.
- Перед входом — отдельная отметка «Даю согласие на обработку персональных данных» со ссылкой на текст согласия.
- Фото профиля не пропадает после перезагрузки и истечения сессии; можно вернуть фото из ЭИОС.
- Прогресс «Знакомства с порталом» считается по реальным действиям и хранится по аккаунту.

**Расписание**
- Прошедшие пары бледнеют, текущая выделена с обратным отсчётом, следующая — акцентом.
- Видно, для какой подгруппы пара; если у подгрупп разные пары в одно время — они стоят рядом колонками,
  у свободной подгруппы — «Нет пары». Замены помечены.
- Приветствие на главной: сколько пар сегодня, текущая или следующая пара с аудиторией.
- Никаких выдуманных пар: если ЭИОС не отвечает — последняя сохранённая копия с пометкой или честная ошибка.

**ВИТШик (чат)**
- Считает по расписанию: «где следующая пара», «что завтра», «когда философия», «а в пятницу?».
- Аудитории со схемой этажа, «где сейчас Киприна», ответы из FAQ и форума.
- Под ответом кнопки: аудитория на карте, расписание, карточка преподавателя, обсуждение на форуме.
- Гость может спрашивать про пары выбранной группы, не входя.

**Документы от ВИТШика**
- «Напиши объяснительную, вчера болел» → карточка с готовым документом: ФИО в родительном падеже, курс,
  группа, пропущенные пары и преподаватели из расписания, причина.
- «Хочу пересдать философию» → заявление на пересдачу: дисциплина, преподаватель, форма контроля.
- Поля правятся прямо в карточке; скачивание в Word (Times New Roman 14) или PDF.
- Адресат по умолчанию: «Директору Высшей ИТ-школы КГУ А. С. Борисову».

**Карта и аудитории** (`/map`)
- Схемы этажей нарисованы заново по планам корпуса: цвет — тип аудитории, лестницы, туалеты, вход.
  Нажатие на аудиторию (или `/map?room=Б-301`) — заливка и булавка, на телефоне схема сама прокручивается к ней.
- Карточка аудитории: мест, ПК, ноутбуки, ОС, оборудование и пары сегодня из ЭИОС —
  «Сейчас занята: Базы данных до 11:40» или «Сейчас свободна, следующая пара в 13:40».
- Поиск понимает номер, место и ОС: «Б-305», «ИТ улей», «Linux». Подсветка: с компьютерами, Linux, Windows,
  проектор, лекционные, коворкинги; на вкладках этажей — сколько подходит на каждом.
  Ссылки вида `/map?os=Linux`, `/map?eq=проектор`, `/map?type=лекционная` открывают подсветку сразу.
- Коворкинги на схеме: «8 бит» (Б-108) и «ИТ улей» (центр 1 этажа), «64 бит» (4 этаж).
- Схемы в чате ВИТШика — те же, с выделенной аудиторией; старые картинки удалены.

**Преподаватели**
- У каждого статус «сейчас» по расписанию ЭИОС и пары на сегодня в карточке.

**Телефон**
- Установка на главный экран (кнопка в профиле; для iPhone — подсказка про Safari).
- Работает только с интернетом: офлайн-режим убран, у кого он успел установиться, он удалится сам.
- Нужен HTTPS: по голому IP по HTTP установка недоступна.

**Дизайн**
- Новый интерфейс: светло-голубая навигация, цвет раздела на активном пункте, контраст AA везде.
- Нижняя панель вкладок на телефоне, поиск в FAQ, поиск аудитории на карте (`/map?room=Б-305`).

## Cookie и персональные данные

- **Уведомление о cookie** на всех страницах до нажатия «Понятно»: портал использует одну cookie — для входа,
  рекламы и аналитики нет. На телефоне не закрывает кнопку чата.
- **Страница `/privacy`** («Ваши данные и cookie»): кто обрабатывает данные, какие и зачем, что уходит в GigaChat,
  таблица cookie и данных в браузере, сроки и права, **отдельный текст согласия** (`/privacy#consent`).
  Ссылка — в подвале каждой страницы, в уведомлении и у формы входа.
- **Согласие при входе**: галочка не стоит заранее; без неё сервер отвечает 400 и не обращается к ЭИОС.
  Дата и редакция согласия записываются в профиль (миграция `0005`).
- Тексты — черновик для согласования с юристом КГУ (оператор, адрес, сроки). Редакция меняется в двух местах:
  `client/src/pages/Privacy.jsx` (`EDITION`) и `server/app/routers/auth.py` (`PD_CONSENT_VERSION`).

## ВИТШик и GigaChat: как устроено

```
вопрос
 ├─ объяснительная / пересдача → черновик документа (код)
 ├─ «привет», «что ты умеешь», «спасибо» → ответ без поиска (код)
 ├─ понятный вопрос про пары, аудиторию, преподавателя → точный ответ из ЭИОС (код, без модели)
 └─ всё остальное, студент вошёл → агент GigaChat:
      понимает вопрос своими словами → вызывает функции портала (до 2 раз):
        schedule · find_room (с компьютерами и техникой) · find_teacher · search_portal (и по базе аудиторий)
      → формулирует ответ только из их результатов → проверка → студенту
```

- **Точные факты** (пары, время, аудитории, где преподаватель) берутся из данных. На частые формулировки
  отвечает код без модели; остальное модель получает через функции, а не придумывает.
- **Проверка ответа модели**: число, почта, ссылка или @ник, которых нет в результатах функций, — вместо ответа
  студент получает сами данные. Если функций не вызывали и ничего не нашлось, модель может говорить только о себе,
  иначе «в базе этого нет». Вопрос не по теме — «не нашёл»; просьбы «забудь правила» не работают.
- **Дни недели** («завтра», «в пятницу») считает портал, а не модель, даже если модель ошиблась в дате.
- **Откаты**: GigaChat недоступен, занят, медлит дольше 16 с → ответ из данных портала без пересказа.
  Модель не принимает функции → на 30 минут бот переходит на простой пересказ найденного.
- **Один поток**: ключ физлица обслуживает один запрос за раз. Вопросы ждут очереди не дольше 5 с,
  один запрос — не дольше 12 с, после ошибки 429 или 5xx — пауза 30 с. Клиент ждёт ответа до 24 с.
- **Гости** получают ответы только из данных портала: платный API без входа не тратится.
- **Чаты не смешиваются**: каждый запрос несёт только свою историю, сервер ничего не хранит между запросами.
  Ответ, пришедший после завершения чата, отбрасывается; при смене аккаунта чат начинается заново.
- Проверка реальными запросами (ключ и токен не печатаются), включая то, принимает ли модель функции:
  `docker compose exec portal python -m app.services.gigachat_check`

## Безопасность

- JWT только в httpOnly-cookie, проверка CSRF-заголовка, bcrypt, `SECRET_KEY` не короче 32 символов.
- Аккаунт привязан к ID в ЭИОС, лимиты попыток входа, блокировка пользователей.
- nginx: HTTPS с редиректом, строгий CSP, заголовки безопасности на всех путях (не теряются в location).
- Проверка TLS для GigaChat не отключается: сертификаты Минцифры (корневой и выпускающие 2022 и 2024) встроены
  в `server/app/assets/certs/russian_trusted_ca.pem`, их отпечатки SHA-256 проверяет тест.
- Бэкенд в контейнере работает не от root; миграции Alembic применяются при старте.

## Настройки `.env`

| Переменная | Зачем |
|---|---|
| `SECRET_KEY` | подпись сессий (в одном контейнере генерируется сам) |
| `ADMIN_USERNAME`, `ADMIN_PASSWORD` | вход в панель управления |
| `GIGACHAT_AUTH_KEY` | ключ GigaChat; без него ВИТШик отвечает только данными портала |
| `GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` для физлица |
| `GIGACHAT_MODEL` | по умолчанию `GigaChat-2` |
| `GIGACHAT_MAX_STREAMS` | одновременных запросов: 1 для физлица, 10 для юрлица |
| `GIGACHAT_CA_BUNDLE` | не нужен: сертификаты Минцифры встроены; путь к доп. PEM, если выйдет новый сертификат |
| `DOCUMENT_ADDRESSEE_TITLE`, `DOCUMENT_ADDRESSEE_NAME` | адресат документов (дательный падеж); `-` — пустая строка |

## Что сделать после обновления

1. `git checkout main && git pull` — заодно удалит старый `infrastructure/nginx.conf`.
2. Перевыпустить ключ GigaChat и секреты: старые остались в истории git (шаг 0 в `DEPLOYMENT_GUIDE.md`).
3. Заполнить `.env` (таблица выше).
4. Пересобрать: `docker compose up --build` (новые зависимости: python-docx, reportlab, pytrovich; миграции применятся сами).
5. Проверить GigaChat командой `gigachat_check` (см. выше).
6. Согласовать тексты `/privacy` с юристом КГУ.
7. Для установки на телефон открыть портал по HTTPS.

## Новое в API

| Метод | Что делает |
|---|---|
| `GET /api/v1/schedule/teachers/today` | пары преподавателей портала на сегодня |
| `GET /api/v1/documents/pairs?date=` | пары студента за день (для объяснительной) |
| `POST /api/v1/documents/explanatory?format=docx\|pdf` | объяснительная |
| `POST /api/v1/documents/retake?format=docx\|pdf` | заявление на пересдачу |
| `POST /api/v1/chat` | ответ теперь с кнопками `actions` и черновиком `document` |
| `POST /api/v1/auth/eios-login` | новое обязательное поле `consent: true` |

`0005` дата и редакция согласия на обработку данных, `0006` удаление таблицы прогресса адаптации.
